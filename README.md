# 地雷かいだん

『地雷グリコ』のルールで遊べる、非公式のファンゲームです。階段を上るじゃんけんと、隠した地雷の心理戦をブラウザで遊べます。
青崎有吾『地雷グリコ』（KADOKAWA）に着想を得たファンメイド作品で、原作のキャラクター名・イラスト・本文は使っていません。

## 遊び方

1. 1〜45段のうち3か所に、相手に見えないよう地雷を置く（同じ段に置いてしまったら、重なった段の番号だけが告げられ、両者置き直し）
2. じゃんけんで勝つと必ず進む。グー＝3段、チョキ＝6段、パー＝6段。46段目に着いたら勝ち
3. 相手の地雷に止まると爆発して10段下がる（連鎖あり。爆発した地雷は消える）。自分の地雷は罰なしだが、位置が相手に知られる
4. 〈あいこルール〉1ターン内で同じ手によるあいこが5回連続したら、そのじゃんけんは立っている位置がゴールに近いほう（同じ段なら先着）の勝ち。勝ったほうは3段か6段、好きなほうを選んで進む。違う手のあいこになったら、回数は1から数え直す
5. 発言は自由。次の手や地雷の位置を宣言できる（嘘もOK）。AIの受け取り方は強さしだい

### 画面

- 階段は6列×8段のすごろく盤で、全47段が一画面に収まります。行ごとに折り返して上へ進みます
- 3の倍数の段は、いつも2列目と5列目にそろいます（最初に被弾するまで、誰もが3の倍数の段にしか止まれません）
- 高さは、マスの段差の厚みで表します。スタートが一番薄く、ゴールが一番厚いので、どちらが先行しているか一目で分かります（3の倍数の段は段差が朱）。上部には段数・残りの地雷の数・2人の差、その下にスタートからゴールまでの進み具合の帯があります
- 地雷の爆発は、自分が踏んだ「被弾」（黒煙と赤黒い画面）と、相手に踏ませた「命中」（金色の光と紙吹雪）で演出と音が変わります。対局に勝つと紙吹雪と歓声、負けると画面が沈んで鐘が鳴ります
- 手はカードで出します。1回タップで持ち上げ、もう1回タップで勝負します。演出中に続けてタップすると、次の勝負に予約されます（キーボードの 1/2/3 でも操作できます）
- マスをタップすると、推理メモ（？怪しい／○たぶん安全／！宣言された）を付けられます

### 色と見やすさ

- 2人の色は、色覚の違いがあっても見分けやすい青と橙です。さらに、コマの形（丸とひし形）と、マスの印の字（雷・爆・済・言）でも区別できます
- 色覚の3つの型と白黒の見え方をシミュレーションして、見分けられることを確認しています
- 設定の「振動・点滅を減らす」で、画面の振動・光の点滅・端末の振動を止められます

## 開発

```
npm install
npm run dev          # 開発サーバー
npm test             # ユニットテスト（ルール・AI・画面の補助）
npm run sim          # AI同士の対戦（既定2000局/組。--declare で宣言ありも）
npm run sim:check    # 強さの順の合否判定（CIで使用）
npm run build        # 型チェック + ビルド（dist/）
npm run e2e          # 画面の通し確認（要ビルド・Chrome）
```

`npm run e2e` は Chrome の場所を自動で探します。見つからないときは環境変数 `CHROME_PATH` で指定してください。

### 構成

```
src/core/    ルール本体（純粋関数。画面から完全に分離）。仕様1-7の例はすべて tests/rules.test.ts
src/ai/      AI（地雷の確率・勝率表・3×3ゼロサム・よわい/ふつう/つよい）
src/ui/      画面（DOM直組み。フレームワークなし）。board.ts がすごろく盤
src/fx/      効果音（Web Audioで合成）・画面振動・設定
scripts/     AI対戦（sim.ts）・画面の通し確認（e2e.mjs）
ci/          GitHub Actions のワークフロー（公開手順を参照）
```

### AI

| 強さ | 配置 | 手の選び方 | 宣言の扱い |
|---|---|---|---|
| よわい | 完全ランダム | グー4:チョキ4:パー2（地雷を考えない） | 文字通り信じる |
| ふつう | 3の倍数を含む（壁型・連鎖型が出やすい） | 公開情報から相手の地雷を推理し、混ぜ方の原則で選ぶ | 信じる／裏を読む／無視 |
| つよい | 10段おきの連鎖型 | 毎回、3×3のゼロサムゲームを解いて最適に混ぜる | 無視 |

目安の対戦成績（`npm run sim`、各4000局）: つよい対よわい 78%、つよい対ふつう 67%、ふつう対よわい 62%。

## GitHub Pages で公開する

1. `ci/deploy.yml` を `.github/workflows/deploy.yml` に移す（`.github` フォルダを作る。ワークフローの置き場所は保護されているため、自動では置いていません）
2. GitHub にリポジトリを作り（例: `jirai-kaidan`）、この内容を `main` ブランチに push する
3. リポジトリの Settings → Pages → Build and deployment → Source を **GitHub Actions** にする
4. `main` に push するたびに、`.github/workflows/deploy.yml` がテスト・AIの強さの確認・ビルドを行い、公開する
   公開先は `https://<ユーザー名>.github.io/<リポジトリ名>/`

ビルド時の `BASE_PATH` にリポジトリ名が自動で入ります。独自ドメインやルートで配信する場合は、`BASE_PATH` を `/` にしてください。

## 素材とライセンス

- 効果音は、すべて Web Audio API でその場で合成しています（音声ファイルなし）
- フォントは、各OS標準のフォントを使います（配布していません）
- 絵文字は、各OSの標準の絵文字を表示しています
- 原作のキャラクター名・イラスト・本文は使っていません
- タイトル画面の原作への言及は `src/ui/text.ts` の `FAN_NOTE` と `LEAD` で変更できます
